# Intent: factory new — scaffold a work unit

ID: F-001   Author: founder   Status: accepted
Date: 2026-08-26

## Problem
Starting a unit of work means hand-copying three templates, inventing the next id, and
filling in the title and date by hand. It's slow and easy to get inconsistent — a wrong id,
a forgotten date, or a spec that doesn't reference the right intent.

## Proposed outcome
A single command, `factory new "<title>"`, that scaffolds the intent, spec, and plan files
for the next id with title and date already filled in, and prints the delivery-tracker row
to paste. Starting a unit becomes one line.

## Affected users and systems
Anyone running the line. Adds a CLI package and a console-script entry; reads templates/.
No change to existing product behaviour.

## Constraints
- Python standard library only — no new runtime dependencies.
- Must never overwrite an existing artifact.
- Must keep `make check` green.

## Out of scope
- Auto-editing DELIVERY-TRACKER.md (print the row; the human pastes it) — a later unit.
- Any git operations (branch/worktree creation).

## Open questions
- Id format fixed to F-NNN, zero-padded to three. Resolved: yes, matches the trackers.

## Note (bootstrap)
F-001 is authored by hand because the tool it delivers doesn't exist yet. From F-002 on,
`factory new` scaffolds the chain.
