# Intent: Tracker auto-update

ID: F-003   Author: founder   Status: accepted
Date: 2026-08-31

## Problem
Every unit ends with a manual step: copy the printed row into DELIVERY-TRACKER.md. It's easy
to skip or forget (we have, repeatedly), so the tracker drifts out of sync with reality.
F-001 deferred "auto-editing DELIVERY-TRACKER.md" as a later unit -- this is that unit.

## Proposed outcome
`factory new` adds the unit to the tracker's In-flight table automatically. No copy-paste,
no drift. A `--no-tracker` escape hatch prints the row instead for anyone who wants manual
control.

## Affected users and systems
The CLI's `new` command and DELIVERY-TRACKER.md. No change to eval or to artifact creation.

## Constraints
- Python standard library only.
- Must be safe: never corrupt the tracker, never duplicate a row, and if the tracker or its
  In-flight table is missing, fall back to printing the row (don't fail the command).
- Must keep `make check` green.

## Out of scope
- Moving a unit to Shipped on merge (a future `factory ship` unit).
- Editing ADOPTION-TRACKER.md.

## Open questions
- Insert position: top of the In-flight table (newest first). Resolved: yes.
