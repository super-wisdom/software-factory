# Intent: Project init command

ID: F-004   Author: founder   Status: accepted
Date: 2026-08-31

## Problem
Starting a new project the factory way means hand-copying the whole "line" (CLAUDE.md, .claude/,
templates/, Makefile, workflows, trackers) into a fresh repo and stripping out the old product
code. It's slow, error-prone, and drifts as the line evolves.

## Proposed outcome
`factory init <name>` scaffolds a brand-new project with the line already installed and a
minimal, green src/tests placeholder -- so a new repo is turnkey in one command. From there:
git init, create the repo, and start shipping units.

## Affected users and systems
The CLI (adds an `init` subcommand + a bundled scaffold). No change to existing products.

## Constraints
- Python standard library only; the scaffold ships inside the package (works after a global
  pipx/uv install, offline).
- The generated project's own `make check` must be green immediately.
- Never overwrite a non-empty target directory.

## Out of scope
- The AI-review workflow (comes from the org-level GitHub App + secret, not per-repo files).
- The factory's own meta-docs (FACTORY-DESIGN, ADOPTION-*, dashboard) -- those are about
  building the factory, not running a project.
- Creating the GitHub repo / remote (left to the human: gh repo create).

## Open questions
- How to bundle the scaffold so it survives a pipx install? Resolved: embed as generated
  package data (scaffold.py), not external files.
