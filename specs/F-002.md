# Spec: Eval runner

ID: F-002   Derived from: intent/F-002.md   Status: accepted
Skills applied: artifact-chain

## Summary
Add a `factory eval` subcommand backed by a small evals module that loads task definitions
from evals/tasks/*.json, runs each from the repo root, and reports a pass rate. Replace the
placeholder step in agent-evals.yml with a real invocation. Ship five starter tasks that
guard config invariants make check does not cover.

## Requirements
- Task = {id, description, cmd, expect_exit=0, expect_contains?}; a JSON file may hold one
  task or a list.
- `factory eval` runs every task from the repo root, prints PASS/FAIL per task and a summary,
  and exits 0 only if pass rate >= --min-pass-rate (default 1.0).
- Commands run without a shell (shlex-split argv) for predictability.
- agent-evals.yml installs the package and runs `python -m software_factory.cli eval`.
- Starter tasks: CLAUDE.md has a Commands section; settings.json is valid JSON; settings.json
  denies .env; intent template keeps the F-XXX placeholder; the artifact-chain skill declares
  a name.

## Non-functional
- Standard library only. Deterministic. Exit non-zero on failure so CI can gate.

## Areas of concern (flagged)
- Tasks are trusted repo content; commands run via argv (no shell) to keep them predictable.

## Acceptance criteria
1. `factory eval` against the five starter tasks reports 5/5 and exits 0.
2. A suite with one failing task exits non-zero at the default threshold, and exits 0 with a
   --min-pass-rate that allows it.
3. load_tasks reads both a single-object file and a list file.
4. run_task honours expect_exit and expect_contains.
5. `make check` is green.
