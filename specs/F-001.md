# Spec: factory new — scaffold a work unit

ID: F-001   Derived from: intent/F-001.md   Status: accepted
Skills applied: artifact-chain

## Summary
Add a `factory` CLI with a `new` subcommand that scaffolds the intent/spec/plan artifact
chain for the next work-unit id, filled with id, title, and today's date, and prints a
ready-to-paste delivery-tracker row.

## Requirements
- `factory new "<title>"` computes the next id by scanning intent/, specs/, plans/ for the
  highest existing F-NNN and adding one (starts at F-001).
- `--id F-042` overrides the computed id; ids not matching F-<digits> are rejected.
- Creates intent/<id>.md, specs/<id>.md, plans/<id>.md from templates/, replacing the
  <short title>/<title>, F-XXX, and <YYYY-MM-DD> placeholders.
- If ANY of the three target files already exists, abort and write nothing.
- Print each created path, then the delivery-tracker row.
- Locate the repo root by walking up from the cwd to the dir holding templates/, intent/,
  specs/, and plans/.

## Non-functional
- Standard library only. Exit non-zero on any error, so hooks and CI can rely on it.

## Areas of concern (flagged)
- None blocking. The fill() placeholders must match templates/ exactly — pinned by a test.

## Acceptance criteria
1. In a repo with no units, `factory new "Export to CSV"` creates F-001 across all three
   folders; each file contains the title, F-001, and today's date.
2. With F-001 and F-003 present, the next id is F-004.
3. Running against an existing id aborts with a non-zero exit and writes nothing.
4. An invalid --id is rejected with a non-zero exit.
5. `make check` is green (lint + tests + build).
