# Spec: Tracker auto-update

ID: F-003   Derived from: intent/F-003.md   Status: accepted
Skills applied: artifact-chain

## Summary
After scaffolding a unit, `factory new` inserts an In-flight row into DELIVERY-TRACKER.md
(id, title, branch, Intent=in-progress, other stages not-yet). It removes the "Nothing in
flight" placeholder, never duplicates, and degrades gracefully when the tracker is absent.

## Requirements
- Insert the row at the top of the "## In flight" table (just after the header separator).
- Row columns match the table: id, title, worktree/branch, then the seven stage cells
  (Intent 🟡, the rest ⬜), then empty Owner and Notes.
- Remove any "_Nothing in flight_" placeholder line from the section.
- If a row for this id is already present, do nothing (idempotent).
- If DELIVERY-TRACKER.md or its In-flight table is missing, print the row and continue
  (exit 0); never raise.
- `--no-tracker` skips the write and prints the row instead.

## Non-functional
- Standard library only. Never leaves the tracker malformed.

## Areas of concern (flagged)
- Markdown-table editing is the fiddly part F-001 flagged; handled by locating the section
  header + separator and inserting a well-formed row, covered by tests.

## Acceptance criteria
1. `factory new "X"` against a tracker with an empty In-flight table adds the row and clears
   the placeholder.
2. Running two units adds two distinct rows; neither is duplicated.
3. `--no-tracker` writes nothing to the tracker and prints the row.
4. With no DELIVERY-TRACKER.md present, the command still exits 0 and prints the row.
5. `make check` is green.
