SHEET 01

What a software factory is

Build software the way a plant builds goods: a standardized, tooled line — not bespoke craft every time.

↺

Reusable, not bespoke

Turn one-off decisions into assets — templates, encoded standards, automated steps — so output stops depending on memory or mood.

▤

A paved road

The modern version is a productized pipeline: standards written once, checks automated, gates in place, so any unit ships the same way.

◆

Agents on the floor

The machines on this line are Claude Code sessions doing the production work inside guardrails — while humans stay accountable at the gates.

  • 01Nothing is built without a reviewed plan. intent → spec → plan → diff+tests → PR, each committed.
  • 02The repo is the single source of truth. Git history is the audit trail — no change board, no dual systems.
  • 03Standards live in files, not heads. Conventions in CLAUDE.md; must-hold rules as skills backed by hooks.
  • 04Every change verifies itself. One-command test/build/lint the agent runs before you look.

SHEET 06

Cost efficiency

Two levers: the stack you pick, and how you spend agent time.

▤ Stack — pick boring & documented

Agent error rate — your biggest hidden cost — is lowest on mainstream tech. A sane default:

  • Runtime · TypeScript (Node) or Python — deep training coverage
  • Framework · a mainstream, batteries-included one for your type
  • Data · managed Postgres on a free tier — no ops overhead
  • Hosting · serverless/edge with a real free tier; pay as you scale
  • CI · GitHub Actions free minutes cover a 1–2 person team

◆ Agent usage — match model to task

  • Plan mode · the cheapest quality lever — one clean pass, not many
  • Right-size · cheap model for boilerplate & evals; strongest for architecture
  • Subagents · a researcher reports a summary, keeping context short
  • Cap evals · run on config change + nightly, not every commit
  • CLAUDE.md pays for itself · every prevented mistake is a retry unbought
